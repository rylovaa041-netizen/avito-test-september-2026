# Классификация ботов на Авито

Решение тестового задания для Data Science Bootcamp от Авито.
Задача — по событиям внутри суточного окна предсказать для каждой `cookie_id`
вероятность того, что она принадлежит боту.

## Постановка задачи

- **Вход:** события пользователя внутри суточного окна
  (`window_start_ts <= event_ts < window_end_ts`).
- **Выход:** `score` от 0 до 1 для каждой `cookie_id` из `test.csv`.
  Чем выше значение, тем вероятнее, что кука принадлежит боту.
- **Целевая метрика:** Precision при Recall ≥ 0.7 (`P@R0.7`).
  Порог подбирает проверяющая система автоматически.
- **Дополнительно:** PR-AUC и ROC-AUC для диагностики.

## Данные

| Файл | Описание | Размер |
|---|---|---|
| `data/train.csv` | Обучающая выборка с `target` | 11 091 кука |
| `data/test.csv` | Тестовая выборка без `target` | 4 909 кук |

| `sample_submission.csv` | Пример формата ответа | — |

Дисбаланс классов: ботов ~8.1%, людей ~91.9%.

## Подход

### Feature Engineering

Все признаки строятся по событиям **внутри окна наблюдения** и агрегируются
до уровня `cookie_id`. Итоговый набор — **56 признаков**.

**Базовые агрегаты:**
- число событий (`n_events`);
- число уникальных `item_id`, `item_category`, `item_location`, `seller_type`;
- число уникальных `search_query`, `eid`, `user_agent`.

**Временные признаки:**
- интервалы между событиями: mean, std, min, max, median (`dt_*`);
- число уникальных часов активности (`n_unique_hours`);
- среднее и std часа события (`hour_mean`, `hour_std`);
- энтропия распределения по часам (`hour_entropy`);
- длительность сессии (`session_duration`).

**Плотность поведения:**
- `items_per_event` — сколько уникальных объявлений на одно событие;
- `repetition_rate` — сколько событий приходится на одно уникальное объявление.

**Ночная активность:**
- `night_ratio` — доля событий в интервале 00:00–05:59.

**Доли типов событий:**
- `ev_ratio_*` — пропорция каждого `event_name` от общего числа событий
  (item_view, search_results_view, photo_swipe, favorite_add и т.д.).

**Флаги ключевых событий:**
- `has_login`, `has_favorite_add`, `has_contact_*`, `has_seller_page_view`,
  `has_photo_swipe`.

**Pointer-признаки:**
- `ptr_x_std`, `ptr_y_std`, `ptr_x_mean`, `ptr_y_mean`;
- `ptr_fill_ratio` — доля событий с заполненными координатами.

**Search page:**
- `search_page_mean`, `search_page_max`, `search_page_std`.

**Платформа и ОС:**
- `platform_norm` — нормализация (web / android / ios / desktop / other);
- one-hot по нормализованным платформам;
- парсинг `user_agent` на OS и браузер, one-hot.

**User-Agent флаги:**
- `is_headless` — признак headless-браузера или автоматизированного клиента;
- `is_mobile` — мобильное устройство;
- `n_unique_ua` — число уникальных UA на куку.

### Модель

- **LightGBM** с `class_weight='balanced'` для учёта дисбаланса классов.
- Валидация — **временная**: `window_start_ts >= '2026-04-17'`.
  Случайный split не используется, чтобы избежать утечки.
- Ранняя остановка по `valid_0's auc` с patience = 50.
- `random_state = 42` зафиксирован для воспроизводимости.

### Метрики на валидации

| Метрика | Значение |
|---|---|
| **P@R0.7** | **0.7671** |
| PR-AUC | 0.7447 |
| ROC-AUC | 0.9244 |

### Что дало наибольший прирост

- **Плотность поведения** (`items_per_event`, `repetition_rate`):
  боты просматривают больше объявлений с повторениями.
- **Ночная активность** (`night_ratio`): боты не спят и активны в 3–4 утра.
- **Временные интервалы** (`dt_min`, `dt_std`): у ботов минимальные
  интервалы и низкий разброс.


## Как запустить

1. Установить зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Открыть `solution.ipynb` и выполнить ячейки сверху вниз
   (Restart Kernel → Run All).

3. После выполнения в корне появится `submission.csv` с колонками
   `cookie_id` и `score`.

## Ограничения и допущения

- Признаки считаются **только по событиям внутри окна наблюдения**.
  События после `window_end_ts` не используются.
- Исторические флаги по событиям до `window_end_ts` тестировались,
  но не дали прироста и были исключены.
- Признак `captcha_shown` отсутствует как в train, так и в test,
  поэтому не используется.
- `company` и `agent`-подобные ID не учитывались, так как их нет в задаче.

## Что можно улучшить

- Тюнинг гиперпараметров LightGBM (Optuna / ручной grid search).
- Попробовать CatBoost для категориальных признаков.
- Добавить target encoding для `item_category` и `item_location`.
- Feature selection: удалить признаки с importance < 1%.
- Попробовать ансамбль LightGBM + CatBoost.
